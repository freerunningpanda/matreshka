# Battle Pass — тестовое задание · Flutter

Главный экран боевого пропуска (БП) по [макету в Figma](https://www.figma.com/design/cCWtK0v3plrmwvPO9DZCRU/) —
три обязательных состояния, мок-данные, `flutter_bloc` (Cubit), лёгкая Clean Architecture.

## Как запустить

```bash
flutter pub get
flutter run
```

Ограничений по окружению/`--dart-define` нет — экран полностью на моке, без бэкенда.
Приложение принудительно переключается в landscape (см. `main.dart`) — макет альбомный
(iPhone 15, 2320×1080).

**Переключение сценариев** (премиум не куплен / премиум куплен-награда / макс. уровень / бонусный
«завершён») — колба 🧪 в правом нижнем углу экрана. Это dev-контрол, не часть макета, но именно
он и есть «способ переключать состояния экрана», о котором просит ТЗ.

## Что реализовано

- **Главный экран БП** — все 3 обязательных состояния + переключение между ними, плюс бонусный
  4-й сценарий «Завершён» (заготовка под edge-case-состояния из макета типа «конец наград»).
- **Реальные ассеты из Figma** — фон-арка, персонаж/сцена левой панели, премиум-баннер (2
  варианта), центральный предмет (жилет / кинематографичная пара / машина) экспортированы через
  Figma MCP и лежат в `assets/images/battle_pass/`. Цвета, типографика (Geologica, шрифт
  забандлен локально), радиусы, тени, отступы — сняты из данных Figma-файла, а не на глаз.
- **Трек наград** — горизонтальный скролл уровней с алмазными бейджами номеров, авто-скролл к
  текущему уровню при загрузке, майлстоун-тайл каждые 10 уровней (золотой градиент + glow —
  как в макете), состояния тайла (locked/current/claimable/claimed), клейм отдельной награды и
  «Забрать все награды» одной кнопкой.
- **Переход на экран «Задания»** — по нажатию на тизер-карточку; экран — минимум по ТЗ (пустой
  экран + «Назад»), см. ниже.
- **Анимации** — кросс-фейд центрального предмета и текстов при смене сценария, ripple/скейл на
  интерактивных элементах, плавные переходы состояний тайлов, анимированный прогресс-бар XP.

## Что осознанно упрощено / оставлено за скобками

- **Экран «Задания»** — реализован по минимуму ТЗ (пустой экран + кнопка «Назад»), но
  **архитектурный скелет полный**: `domain` (entities, repository, usecase),
  `data` (mock-datasource, repository impl, models с `fromJson`), `presentation`
  (cubit/state) — уже заведены в `lib/features/tasks/` и зарегистрированы в DI
  (`_initTasks()`), так что контент экрана достраивается без переписывания слоёв.
- **«Info bar»** (виджет со сторонним игровым ивентом «Дай пять!» в макете) заменён на
  BP-релевантную пилюлю уровень/XP — оригинальный виджет промоутирует не боевой пропуск, а
  отдельную фичу игры, вне схемы данных этого задания.
- **Левая панель навигации и StatusBar устройства** — статичные изображения из макета: это
  одинаковый на всех экранах app-shell chrome, не относящийся к данным БП, поэтому не
  разбирался на интерактивные виджеты. Системный status bar (время/батарея) не дублируется —
  его рисует сама ОС.
- **Иконки наград в треке** — не уникальны на каждый из 40 уровней (в макете это тоже
  моковый/иллюстративный контент). Вместо экспорта 40 картинок — иконка + оттенок по редкости
  награды (`RewardRarity`), что и требовалось моком.
- **Тизер-карточка «Задания» и премиум-баннер** — фоновая иллюстрация экспортирована из Figma
  как картинка, заголовок/описание/кнопка — живые виджеты поверх (так их можно нормально
  анимировать/тестировать, в отличие от плоского скриншота).
- **Кнопка закрытия (✕)** в углу экрана — в макете это модалка поверх домашнего экрана игры; в
  этом задании БП — корневой экран, поэтому кнопка оставлена для визуального соответствия, но не
  из чего «закрываться».

## Модель данных

Схема продумана до вёрстки, proto-подобный набросок:

```proto
rpc BattlePass {
  enum RewardRarity { COMMON = 0; RARE = 1; EPIC = 2; LEGENDARY = 3; }

  message Reward {
    int32 id "id награды";
    lstring name = 64 "Название награды";
    lstring iconAsset = 128 "Путь до иконки/изображения награды";
    int32 amount "Количество (стаков)";
    RewardRarity rarity "Редкость награды";
    bool claimed "Уже получена игроком";
  }

  enum LevelState { LOCKED = 0; CURRENT = 1; CLAIMABLE = 2; CLAIMED = 3; }

  message Level {
    int32 number "Номер уровня БП";
    int32 requiredXp "XP, необходимый для достижения уровня";
    Reward freeReward "Награда бесплатной ветки (может отсутствовать)";
    Reward premiumReward "Награда премиум-ветки (может отсутствовать)";
    LevelState state "Состояние уровня относительно прогресса игрока";
  }

  outgoing Season {
    int32 seasonId "id текущего сезона БП";
    lstring seasonName = 64 "Название сезона";
    bool premiumOwned "Куплен ли премиум-пропуск";
    int32 currentLevel "Текущий уровень игрока";
    int32 currentXp "Текущий опыт внутри уровня";
    int32 maxLevel "Максимальный уровень сезона";
    repeated Level levels max 200 "Все уровни сезона по порядку";
    int64 seasonEndsAtMs "Таймстамп окончания сезона, UTC ms";
  }
}

rpc BattlePassTasks {
  message Task {
    int32 id "id задания";
    lstring title = 128 "Текст задания";
    int32 progressCurrent "Текущий прогресс выполнения";
    int32 progressTarget "Целевое значение для выполнения";
    int32 rewardXp "Награда опытом за выполнение";
    bool completed "Задание выполнено";
    bool claimed "Награда за задание забрана";
  }

  outgoing TasksScreen {
    bool premiumOwned "Куплен ли премиум-пропуск";
    bool premiumXpBuffActive "Активен ли бафф +XP от премиума";
    repeated Task tasks max 50 "Список заданий";
  }
}
```

`Level.state` вместе с `Season.premiumOwned` / `currentLevel` / `maxLevel` — это и есть машина
состояний, из которой выводятся все сценарии экрана (обязательные и бонусные).

Реализация в коде: `lib/features/battle_pass/domain/entities/` — Dart-эквивалент этой схемы
(`Season`, `Level`, `Reward`), а `lib/features/battle_pass/data/models/` — слой `Model.fromJson`,
который разбирает мок «серверных» Map'ов из `data/mock/battle_pass_mock_api.dart` — то есть
подключение реального бэкенда в будущем не потребует менять domain/presentation слои.

## Архитектура

Лёгкая Clean Architecture на фичу (`lib/features/battle_pass/`, `lib/features/tasks/`):

```
domain/       entities, abstract repository, usecases
data/         mock-datasource, models (Entity → Model, fromJson/toJson), repository impl
presentation/ cubit (state), screens, widgets
```

- **State management** — `flutter_bloc` Cubit (по ТЗ), не полноценный BLoC.
- **DI** — `get_it`, единый контейнер `lib/core/di/injection_container.dart`, секции
  `_initBattlePass()` / `_initTasks()`.
- **Навигация** — обычный `Navigator.push` через `lib/core/navigation/app_router.dart` (ручной,
  без кодогенераторов — ТЗ их прямо запрещает).
- **Result/BaseRepository** — небольшой `sealed Result<T>` + `BaseRepository.execute()` для
  единообразной обработки ошибок в data-слое (задел под реальные сетевые ошибки).
- Экран верстается на фиксированном холсте 2320×1080 (`DesignCanvas`, `FittedBox`), совпадающем
  с холстом Figma-фрейма, — так все размеры/отступы виджетов берутся из макета напрямую, без
  пересчёта в logical pixels.

## Использование ИИ

Всё задание выполнено в паре с Claude Code (Claude Sonnet 5, agentic-режим в CLI):

- **Figma → данные**: доступ к макету через Figma Dev Mode MCP-сервер — снятие точных фреймов,
  стилей текста, цветов/градиентов/теней, layout-координат и экспорт финальных изображений
  (фон, персонажи, баннеры) напрямую в `assets/`.
- **Планирование**: перед кодом — явный план (архитектура, схема данных, декомпозиция
  виджетов), согласованный в диалоге, в т.ч. вопрос про степень готовности экрана «Задания».
  Раздел «Что осознанно упрощено» выше — прямое следствие этого плана.
- **Реализация**: весь код (entities/repository/usecase/cubit/widgets), конфиг pubspec,
  загрузка и локальный бандлинг шрифта Geologica — написаны и отлажены ассистентом.
- **Верификация**: `flutter analyze` после каждого крупного изменения; экран прогонялся на
  Android-эмуляторе (landscape), скриншоты по всем 3 обязательным состояниям сверялись бок-о-бок
  с соответствующими фреймами в Figma; интерактивные сценарии (клейм награды, клейм всех наград,
  переключение сценария, переход на «Задания» и назад) проверялись через `adb input tap` по
  живому запущенному приложению.
